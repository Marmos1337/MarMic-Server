# MarMic Server 0.18.2

Целевой hotfix синхронизации глобального профиля на PostgreSQL и совместимости
проверки защищённых Docker images. Это отдельный Server release: опубликованные
Desktop/Web 0.18.2 и их артефакты не пересобираются и не заменяются.

## Исправления runtime

PostgreSQL JSONB может возвращать ключи объекта в другом порядке. Ранее одинаковые
avatar/banner descriptors могли ошибочно считаться изменёнными при очередной
проверке авторизации. Это вызывало лишние записи профиля и повторные обновления;
при параллельных запросах возникали конфликты сериализации PostgreSQL `40001`.

В 0.18.2 JSON сравнивается по содержимому, а не по порядку ключей в строке.
Неизменившийся профиль остаётся без записи в БД. Реальные изменения имён, медиа
и времени профиля продолжают применяться; защита от устаревших данных и локальные
переопределения профиля сохранены. Некорректный JSON не приравнивается к валидному
объекту или `null`, порядок элементов массивов не игнорируется.

Эта правка не отключает транзакционную защиту и не подавляет любые ошибки `40001`:
она устраняет конкретный источник ненужных конкурентных записей. Схема данных
остаётся `server-pg-0002`; повторный импорт SQLite не требуется.

## Management tooling и Docker 29

Distribution revision `36bab3225dd279e6993140be1f5c35207b27b0dd` исправляет проверку
уже используемых защищённых images при обработке подписанного update-архива.
Docker с containerd image store может возвращать digest OCI index вместо digest
image config. Теперь эти идентификаторы сравниваются только после проверки
цепочки OCI descriptors, их SHA-256/размеров, привязки тега, платформы и config.
Поддержка классического Docker image store сохранена.

Архив, содержащий только доказанно идентичные защищённые images, не загружается
повторно, чтобы не менять их теги/index. Настоящие коллизии, противоречивые
инвентари Docker/OCI, смешение защищённых и иных images в таком архиве,
некорректные digest и неоднозначные пути отклоняются. Защита работающего
PostgreSQL не обходится; существующие images и данные нельзя удалять ради
продолжения update.

## Важное ограничение обновления

**Обычный автоматический PG→PG update с Server 0.18.0 не реализован.** Наличие
релиза 0.18.2 не означает, что существующую PostgreSQL-установку можно безопасно
обновить общим SQLite→PG migration path или повторным запуском импорта.

- Для уже переведённых на PG официальных Home/Hub требуется отдельная проверенная
  операторская процедура замены только API runtime. Её нельзя считать выполненной
  только по опубликованным release notes или результатам unit tests.
- До замены нужны свежий согласованный PG backup, проверка восстановления в
  изолированном PostgreSQL и проверенная off-host копия зашифрованного архива.
- Под maintenance lock сохраняются текущие PG generation, credentials, schema,
  server identity и данные. Проверяется приватный canary, затем новый публичный
  API с согласованными декларациями image и обязательной проверкой owner/profile.
  Никакое owner consent не подделывается; история updater сохраняется.
- При необходимости runtime rollback возвращает прежний API **к той же текущей
  PostgreSQL**, а не восстанавливает старую SQLite или PG-копию поверх новых записей.
- Существующий SQLite→PG контракт миграции — отдельный сценарий с согласием
  владельца и собственными проверками. Он не является контрактом PG→PG.

Для другой self-hosted PG-установки не следует копировать host-specific Home/Hub
оператор или вручную менять image tag. Нужна отдельная проверка её конфигурации,
резервного копирования, canary и rollback. Не отключайте signature/compatibility
guards, чтобы заставить неподдерживаемый путь пройти.

## English summary

Server 0.18.2 fixes false global-profile changes caused by PostgreSQL JSONB object
key ordering. Semantically unchanged avatar/banner data no longer produces
unnecessary writes and the associated concurrent `40001` profile-sync failures.
Real profile updates, stale-claim protection, local overrides and validation are
retained. The database schema remains `server-pg-0002`.

Distribution `36bab3225dd279e6993140be1f5c35207b27b0dd` validates protected image
identity for both classic Docker and Docker/containerd OCI index digests. It
checks the descriptor chain and tag/platform/config binding, skips a wholly
identical protected-image archive, and continues to reject real collisions or
ambiguous/mixed inventories. It does not bypass protection for running PostgreSQL.

The targeted Server gate passed 28 tests with real PostgreSQL coverage; this is
not an all-CI, all-feature or production-acceptance claim. Normal automatic
**PG-to-PG updating from 0.18.0 is not implemented**. Already-PG official Home/Hub
require a separately reviewed API-only operator procedure with a fresh verified
PG backup/off-host copy, private canary and owner/profile acceptance. Runtime
rollback keeps the same current PostgreSQL; restoring old SQLite over new writes
is not permitted. Host-specific operators must not be copied blindly to other
self-hosted installations. Desktop/Web 0.18.2 artifacts remain immutable.
