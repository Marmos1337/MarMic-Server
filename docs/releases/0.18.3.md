# MarMic Server 0.18.3

Release candidate для безопасного обновления существующих PostgreSQL-инсталляций
и новых/legacy SQLite-инсталляций. Публичная публикация этого набора assets ещё
не подтверждена этим коммитом: tag и GitHub Release создаются отдельно после
финальной проверки скачанных байтов.

## Русский

### Два отдельных подписанных плана

0.18.3 не переиспользует SQLite→PostgreSQL payload для уже работающей
PostgreSQL-инсталляции. Подготовлены два независимых format-3 manifest/archive:

- `server-update-linux-amd64.signed.json` и
  `marmic-server-0.18.3-linux-amd64.tar.gz` — переход из допустимого диапазона
  SQLite schemas в PostgreSQL 17 `server-pg-0002`;
- `server-update-linux-amd64-postgres.signed.json` и
  `marmic-server-0.18.3-linux-amd64-postgres-runtime.tar.gz` — runtime-only
  обновление строго с PostgreSQL 17 `server-pg-0002` на ту же schema.

Оба плана имеют `approval_required` и `pre_traffic_only`. До открытия публичной
записи updater проверяет подпись, source/target provider и schema, server UUID,
полный backup, scratch restore/fingerprint и private canary. До traffic boundary
допустим откат runtime; после подтверждённой новой записи восстановление старой
SQLite/PG-копии запрещено, а recovery продолжает новый runtime вперёд. Для
external PostgreSQL дополнительно привязаны endpoint/TLS identity и maintenance
роль; неизвестный writer или невозможность доказать quiescence блокируют update.

### Management runtime

Distribution `13e9bd3cfec74c70dd063f5bc940691dcc57f36e` сохраняет строгую
проверку защищённых Docker/OCI images, смешанных архивов и exact tag/platform/
config descriptor chain. PG→PG backup/restore поддерживает корректные `pg_dump`
как с явной записью `SCHEMA public`, так и без неё: default `public` удаляется
только в exact-owned scratch database, если это требуется TOC. Runtime probes
исполняются от user образа; только отдельный root-only maintenance DSN для
external PostgreSQL использует UID 0. Live PostgreSQL не пересоздаётся и не
восстанавливается этим runtime-only путём.

## English

MarMic Server 0.18.3 provides two separate signed format-3 delivery plans. The
default archive is the owner-approved SQLite-to-PostgreSQL 17 transition. The
`postgres-runtime` companion is a same-provider, same-schema update for an
existing PostgreSQL 17 `server-pg-0002` installation. The plans are not
interchangeable and both remain `approval_required` with
`pre_traffic_only` rollback.

Before public writes, the updater verifies the signature and exact provider/
schema tuple, server identity, full backup, scratch restore/fingerprint and a
private canary. A pre-traffic failure restores the old runtime. Once a new write
has crossed the durable traffic boundary, recovery moves the new runtime
forward and never restores an old SQLite or PostgreSQL snapshot over accepted
data. External PostgreSQL additionally requires exact endpoint/TLS and
maintenance-role proof; unknown writers or unprovable quiescence fail closed.

Distribution `13e9bd3cfec74c70dd063f5bc940691dcc57f36e` retains the strict
Docker/containerd OCI identity checks and fixes scratch restore for valid dumps
with or without an explicit `public` SCHEMA TOC entry. Any schema drop is limited
to the exact owned scratch database. Normal probes use the image runtime user;
only the separately pinned root-only external maintenance DSN uses UID 0.

The exact source, image, archive, manifest and bootstrap identities are listed
above. Real signature verification passed, while tampering, expiry, an unknown
key and downgrade were rejected. The native PG runtime gate passed all six
rollback/commit scenarios and the separate cold-process recovery gate passed
all three crash boundaries. These are release-candidate results, not evidence
of GitHub publication or a production deployment. The legacy unsigned feed
stays byte-identical at `0.16.21`, and no private signing material is included.
